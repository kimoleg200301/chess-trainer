# Проверка первой версии

Проверено в рабочей среде 31 октября 2026 года.

- Backend: 15 интеграционных тестов успешно выполнены на PostgreSQL 17. Тесты используют отдельную временную схему, проверяют авторизацию, владение попытками, Origin, скрытие решения, легальные ходы, альтернативный мат, повторения, статистику, экспорт и восстановление прогресса, границы статических/API-маршрутов.
- Frontend: строгая проверка TypeScript и production-сборка Vite успешны.
- Docker: оба отдельных production-образа и единый образ для Render Free собраны; nginx → FastAPI → PostgreSQL и прямой FastAPI → PostgreSQL работают; Stockfish доступен. Единый контейнер дополнительно проверен с лимитом памяти 512 МБ.
- Chromium: проверены вход, фильтр мотивов/рейтинга, неверный ход, подсказка, полное решение с ответами соперника, Stockfish, показ и пошаговый просмотр решения, статистика, скачивание JSON-прогресса, выход. Ошибок JavaScript нет. Сценарий также прошёл через единый контейнер Render Free.
- Экран 390 px: горизонтального переполнения нет. SVG фигур загружаются успешно; права файлов проверены внутри nginx-образа.
- Данные: все 2500 исходных линий проверены на допустимость ходов; начальная позиция учитывает первый ход соперника. Источник и контрольная сумма — `data/puzzles.metadata.json`.
- PostgreSQL: создана резервная копия в custom-формате, её каталог прочитан через `pg_restore --list`; восстановление в отдельную пустую базу успешно, подтверждены все 2500 задач.
- Compose: конфигурации разработки и VPS проходят проверку синтаксиса. Blueprint Render проверен по официальной JSON Schema.

Бесплатная версия развёрнута на **https://tactics-trial.onrender.com/**. Проверка опубликованного адреса подтвердила HTTPS, HTTP 200 главной страницы, корректную выдачу JavaScript/CSS/SVG и `/api/health`: `status=ok`, `database=ok`, `engine_available=true`. `/api/auth/me` без сессии возвращает 401; запросы с origin сайта проходят к валидации API, посторонний origin отклоняется с 403. Вход с пользовательским паролем и авторизованные действия на опубликованном сайте не выполнялись; полный пользовательский сценарий проверен в локальном контейнере.

Основной `render.yaml` содержит только планы Free; платная схема сохранена отдельно. Ограничения бесплатной PostgreSQL и порядок экспорта прогресса описаны в `deploy/CLOUD.md`.

## Интерактивный экран тренировки

Обновление проверено в едином контейнере Render Free с лимитом 512 МБ. Production-сборка успешна. Chromium подтвердил последовательный показ принятого хода и ответа соперника, блокировку действий во время ответа, неверный ход, подсказку, завершение задачи, анализ Stockfish, автопроигрывание решения, паузу, ручной переход, остановку при смене вкладки и повторный запуск варианта. Ошибок JavaScript нет. На ширинах 360, 390, 650, 768 и 1024 px горизонтального переполнения нет.

Отдельно проверены анимации взятия, рокировки, обратного просмотра, ориентация за чёрных и превращение пешки. Настройка уменьшения движения отключает анимации. Кнопка следующей позиции остаётся под доской; счётчик ходов не отображается. Изменения подготовлены для ручного деплоя на Render.

## Главная страница и отдельный экран тренировки

1 ноября 2026 года проверено разделение экранов: после входа отображаются настройки и запуск без пустой доски; после запуска — доска с действиями, без заголовков страницы, шапки, подвала и боковой панели. Возврат к настройкам и продолжение сохраняют ту же попытку, расположение фигур, подсказку и шаг разбора. Автопроигрывание при возврате останавливается. Ошибки диапазона рейтинга и отсутствие подходящих задач показываются на главной; ранее открытая позиция остаётся доступной.

Production-сборка и сценарий Chromium в контейнере Render Free прошли: решение с ответами соперника, подсказка, просмотр решения, Stockfish, статистика, экспорт и выход. Ошибок JavaScript нет. Проверены главный и игровой экраны на ширинах 360–1024 px, горизонтального переполнения нет; в игровом экране отсутствуют элементы заголовков h1–h6. Обновление требует ручного деплоя на Render.

## Удержание экрана включённым

Production-сборка прошла. В Chromium проверена интеграция собранного приложения с настоящим Screen Wake Lock API (ответы серверного API в этом сценарии подставлены): запрос блокировки только на экране тренировки, сохранение блокировки при разборе, освобождение при возврате к настройкам, повторный запрос после продолжения и событий pagehide/pageshow. Ошибок JavaScript нет.

Отдельные проверки с управляемым WakeLockSentinel покрывают скрытие и возвращение вкладки, поздний ответ после выхода или размонтирования, StrictMode, отказ/отсутствие API, повтор после системного освобождения и отсутствие дублирующих запросов. Проверено поведение API; физическое отключение экрана устройства в облачной среде не измерялось.
