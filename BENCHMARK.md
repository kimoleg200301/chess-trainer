# Проверка производительности Stockfish

Основной тест — встроенный **Stockfish `bench`** с профилем тренажёра: **1 поток, Hash 32 MiB, NNUE, MultiPV 2, глубина 13**, восемь фиксированных позиций. Он выполняется три раза последовательно. Это измеряет вычисления самого движка в конфигурации, близкой к анализу партий; сеть, PostgreSQL и интерфейс не входят в показатель NPS.

## Запуск на Render

После обновления приложения через **Render → tactics-trial → Manual Deploy → Deploy latest commit** выполните из корня репозитория:

```bash
python3 scripts/benchmark-server.py --url https://tactics-trial.onrender.com --username trainer --output benchmark-render.json
```

Клиент запросит пароль тренажёра без вывода на экран. Пароль и cookies не записываются в файл. Результат сохраняется в JSON и выводится в терминал. Нужен Python 3; дополнительные библиотеки на клиенте не требуются.

Тест запускается на сервере, а клиент только ожидает результат. Один запуск ограничен 60 секундами, всего их три. Во время теста движок занят диагностикой; если он уже выполняет анализ, запуск отклоняется. Результат хранится временно в памяти сервера, поэтому сохраните JSON; перезапуск приложения удаляет временный результат. Остановка клиента не отменяет уже начатый ограниченный по времени серверный тест.

Клиент печатает идентификатор задания. Если соединение прервалось, повторите команду с `--job-id ИДЕНТИФИКАТОР`: она запросит готовый результат или дождётся текущего теста, не запуская новый. Результаты доступны до 30 минут, если приложение не перезапускалось.

## Повторение на другом сервере

Используйте тот же коммит репозитория. Из его корня соберите backend-образ и выполните тот же профиль:

```bash
docker build -f backend/Dockerfile -t chess-trainer-bench .
docker run --rm chess-trainer-bench python -m app.stockfish_benchmark --profile app > benchmark-vps.json
```

База данных и настройка аккаунта для этого запуска не нужны. Используйте ограничения CPU и памяти, с которыми планируете эксплуатировать приложение; JSON отдельно показывает доступную квоту CPU, когда среда её раскрывает. Число видимых процессоров хоста само по себе не равно выделенной мощности контейнера.

Если нужная версия Stockfish уже установлена, можно обойтись без Docker:

```bash
cd backend
python3 -m app.stockfish_benchmark --engine /usr/games/stockfish --profile app --output ../benchmark-vps.json
```

Обычный стандартный тест Stockfish также доступен:

```bash
stockfish bench 32 1 13 default depth
```

Или три измерения с JSON-отчётом: `python3 -m app.stockfish_benchmark --profile standard`. Стандартный набор **не равен** профилю `app`: например, Stockfish 15.1 в нём проверяет как классическую оценку, так и NNUE, с MultiPV 1. Сравнивайте только одинаковые профили.

## Как сравнивать результаты

Проверьте совпадение профиля, параметров, версии движка, SHA-256 бинарного файла и набора позиций. В одинаковой однопоточной сборке контрольное число `bench_signature_nodes` должно совпадать; при несовпадении сравнение не является контролируемым. На разных архитектурах бинарные файлы будут разными: используйте одну версию исходников и одинаковую нейросеть и явно учитывайте отличие сборок.

- `median_nps` — медианная скорость трёх запусков, узлов поиска в секунду. Чем больше, тем быстрее движок в этом тесте.
- `min_nps` / `max_nps` — разброс скорости; он помогает заметить нестабильность общей CPU-квоты или соседнюю нагрузку.
- `engine_time_ms` — время измеренного поиска; `wall_time_ms` дополнительно включает запуск процесса и сопутствующие операции.
- `checksum_consistent` — совпали ли контрольные результаты всех трёх запусков.

Отношение медианного NPS нового сервера к NPS Render показывает ускорение **этого профиля**. Оно не гарантирует такое же ускорение каждой партии: приложение использует переменные лимиты поиска и повторную проверку сложных ходов. Открытие уже готового отчёта не измеряет работу движка.

Числа, полученные в локальном контейнере с искусственным ограничением CPU, не являются измерением Render. Для оценки Render нужен JSON, возвращённый его диагностическим endpoint после реального запуска.
