# Тактика — личный шахматный тренажёр

Отдельный React-фронтенд, Python API и PostgreSQL. Задачи на тактические мотивы из реальных партий, проверка решения на сервере, интервальное повторение и анализ Stockfish после завершения задания.

Основной сайт: **http://100.105.139.68:8080/**, доступен только через Tailscale. Подключите устройство к разрешённой сети Tailscale и войдите в личный аккаунт тренажёра. Обновление рабочего сервера описано в [deploy/SERVER.md](deploy/SERVER.md).

## Возможности

- 2500 проверенных задач Lichess (CC0), фильтры по мотиву и рейтингу.
- Отдельная база задач, созданных Stockfish из открытых реальных партий: дебют, миттельшпиль и эндшпиль. Базу можно выбрать на главной, включая смешанную тренировку.
- Импорт открытых завершённых партий Chess.com по нику, поиск улучшений в ходах выбранного игрока и создание личных задач из подходящих моментов.
- Раздел **Анализ** разделён на список партий, экран расчёта с процентом выполнения и интерактивный разбор. В разборе доступны стрелки, свайпы, автопроигрывание, список ходов, лучший вариант и переворот доски. Справа от доски — оценка Stockfish в пешках: «+» за белых, «−» за чёрных; мат обозначается отдельно, нерассчитанная оценка — прочерком. Точность и категории ходов находятся в раскрываемом отчёте. Анализ продолжается на сервере при уходе с экрана.
- Доска за белых/чёрных, допустимые ходы, превращение пешки, ответы соперника.
- Звуки ходов и взятий, мягкий сигнал ошибки и мелодия завершения задачи или анализа. Кнопка динамика открывает включение/отключение, громкость и «Проверить звук»; настройки сохраняются в браузере. Используются оригинальные WAV-файлы и HTML Audio с активацией после касания; в скрытой вкладке звуки не накапливаются. Файлы воспроизводятся без внешних сервисов, генератор: `frontend/scripts/generate-sounds.py`.
- Подсказка, показ решения, статистика и повторение трудных задач.
- Таймер решения, среднее время и длительность последних попыток. Время в свёрнутом браузере и скрытой вкладке входит в замер; настройки и ожидание сервера не входят; после решения или показа ответа время фиксируется. Для старых попыток без измерения показывается прочерк.
- Экран остаётся включённым во время открытой тренировки и разбора через Screen Wake Lock API. Нужны HTTPS и поддержка браузера; при уходе с экрана тренировки или скрытии вкладки блокировка снимается.
- Личный вход; пароли хешируются, сессии хранятся в PostgreSQL.
- Все данные занятий сохраняются в PostgreSQL 17. SQLite не используется.

Рейтинг исходных задач взят из Lichess. Сложность созданных движком задач приблизительная и отмечена знаком ≈. Эти значения не равны игровому рейтингу пользователя. Проверка Stockfish ограничена вычислительным бюджетом. Найденные ошибки проверяются более глубоким поиском; для задач нужен заметно более сильный ход и подтверждённое завершение комбинации. Наличие другого выигрывающего продолжения само по себе не исключает задачу. Генератор не гарантирует исчерпывающий разбор каждой партии; защитные упражнения и несколько равноценных правильных ответов пока остаются материалом для разбора.

## Задачи из своих и открытых партий

На главной выберите **База задач**: Lichess, Открытые партии, Мои партии Chess.com или Все базы. В поставку входит подготовленная открытая коллекция; полные исходные партии и происхождение описаны в [data/README.md](data/README.md). Все коллекции хранятся отдельно по источнику в одной PostgreSQL; личные задачи видит только их владелец.

В разделе **Мои партии** введите ник Chess.com, при желании месяц и число партий (1–50, по умолчанию 10). Пароль Chess.com, API-ключ и подписка не нужны: используется бесплатный публичный [Published Data API](https://www.chess.com/news/view/published-data-api). Без месяца берётся последний доступный архив. Импортируются завершённые стандартные партии; варианты и незавершённые игры пропускаются. Приложение не связано с Chess.com.

В результатах показаны партии и ходы, которые можно улучшить. Оценки приведены со стороны указанного игрока. Подходящие задачи из личных и открытых партий **сохраняются автоматически** — нажмите **Решить задачу** или выберите нужную базу на главной. Счётчики отдельно показывают подходящие моменты и сохранённые задачи. У остальных моментов указана причина: несколько близких продолжений, защитная позиция, недостаточная глубина или отсутствие завершённой короткой комбинации.

В личной базе практика начинается с ещё не открытых задач из самой свежей по дате партии; задачи одной партии идут по порядку ходов. Затем следуют более старые партии. Решённые задачи и задачи с показанным ответом больше не выдаются автоматически, в том числе при выборе **Все базы** и после создания новой версии задачи из того же хода той же партии. Незавершённую задачу можно продолжить с сохранённой позиции. Когда личные задачи с выбранными фильтрами закончились, тренажёр сообщает об этом. Повторное прохождение доступно в режиме **Повторение** по расписанию или через явную кнопку **Решить задачу** в разборе партии.

Кнопка **Пересчитать анализ** заново проверяет сохранённые партии текущим алгоритмом. Предыдущие результаты помечаются как ожидающие проверки и обновляются по мере обработки; уже сохранённые задачи и история решений не удаляются. Подборки, рассчитанные старой версией алгоритма, отмечены в интерфейсе. Повторный импорт той же подборки открывает её сохранённый результат; для пересчёта используйте отдельную кнопку.

Анализ выполняется на сервере небольшими шагами и продолжается при сворачивании браузера, закрытии вкладки и переходе к тренировке. После возвращения результаты обновляются автоматически. Кнопка **Пауза** останавливает новые шаги; текущий шаг может завершиться и сохраниться. **Продолжить анализ** возвращает подборку в обработку. Запрос на фоновую работу и прогресс хранятся в PostgreSQL: после перезапуска сервера обработка продолжается с последнего сохранённого шага. Старые незавершённые подборки после обновления остаются на паузе до явного запуска. Скорость обработки зависит от мощности сервера и сложности партии; для начала удобно выбрать 1–3 игры.

## Анализ качества ходов

Откройте **Анализ**, загрузите партии Chess.com по нику или выберите уже импортированную партию и нажмите **Анализировать партию**. Этот раздел проверяет все ходы обеих сторон независимо от поиска тактических задач. Для каждой стороны показаны точность и число бриллиантовых, сильных, лучших, отличных и хороших ходов, неточностей, ошибок, зевков, вынужденных ходов и ходов без оценки. При выборе хода доска показывает позицию после него и подсвечивает начальное и конечное поля. **Назад / Далее** анимируют перемещение фигур; выделенный ход остаётся виден в списке. Позиция **До хода** и **Лучший вариант** доступны отдельно. Список содержит до 200 уникальных партий, начиная с самых свежих по дате игры.

Это собственная приближённая оценка Stockfish, которая может отличаться от Chess.com. Оценку в сантипешках `cp` со стороны ходящего преобразуем в показатель `E = 1 / (1 + exp(-cp / 300))`; мат за игрока соответствует 1, против него — 0. Точность хода равна `100 × exp(-6 × max(0, E_лучшего − E_сыгранного))`, точность стороны — среднее по оценённым невынужденным ходам. «Сильный» отмечает важный практически единственный хороший выбор, «Бриллиантовый» — проверенную эвристикой корректную жертву материала; это не официальные оценки Chess.com.

До полной проверки показана **предварительная** точность и доля оценённых ходов. Итоговый процент появляется после завершения анализа, если все ходы соответствующей стороны удалось оценить. Ходы без надёжной оценки и вынужденные ходы не входят в среднее; одни вынужденные ходы не дают измеримого процента точности.

Каждый проверенный ход сохраняется в PostgreSQL. Анализ продолжается на сервере при скрытии вкладки и выходе из раздела; остановить его можно кнопкой **Пауза**. После возвращения интерфейс загружает актуальный прогресс, а после перезапуска сервера обработчик продолжает незавершённые запущенные отчёты. Повторный импорт той же партии открывает её существующий отчёт. **Пересчитать партию** сбрасывает только этот отчёт. Создание задач и история тренировок от него не зависят; задачи по-прежнему создаются в разделе **Мои партии**.

## Основной сервер и его обновление

Рабочий проект размещён на собственном сервере с Ubuntu 24.04 в WSL2, Docker Compose и PostgreSQL 17. Для него используются `compose.yml` и серверный `compose.wsl.yml`. Frontend опубликован только на loopback WSL; доступ с других устройств предоставляет Tailscale Serve внутри tailnet.

[deploy/SERVER.md](deploy/SERVER.md) — актуальная инструкция по доступу, резервному копированию, обновлению, проверкам и откату рабочего сервера. Сохраняйте его `.env`, Compose override и базу данных; учётные записи уже находятся в PostgreSQL, bootstrap при обновлении отключён.

Описание альтернативных схем размещения сохранено в [архиве deploy/CLOUD.md](deploy/CLOUD.md).

## Первый локальный запуск для разработки

Выполняйте эти команды в отдельном локальном клоне с новой базой. Нужны Docker Engine/Desktop с Compose и Python 3 для генерации конфигурации.

```bash
python3 scripts/configure.py
docker compose up -d --build
```

Откройте http://localhost:8080. Логин указан в `AUTH_USERNAME`, пароль — в `AUTH_PASSWORD` файла `.env`. Генератор создаёт случайные пароли и не перезаписывает существующий файл. `.env` не включается в Git и Docker-образы.

При первом запуске выполняются миграции Alembic и импорт задач. Дождитесь состояния `healthy`:

```bash
docker compose ps
docker compose logs --tail=60 backend
```

Команда `docker compose down` останавливает приложение и сохраняет том PostgreSQL. Флаг `down -v` удаляет данные — не используйте его для обычной остановки.

В управляемой среде Codex сборке может требоваться доверенный CA прокси:

```bash
docker compose -f compose.yml -f compose.managed.yml up -d --build
```

Этот дополнительный файл не нужен на обычном VPS. Он передаёт доверенные сертификаты только на время сборки, без отключения TLS-проверки.

## Данные и резервное копирование

Исходные задачи и их происхождение описаны в [data/README.md](data/README.md). Импорт новых задач:

```bash
uv run scripts/import_lichess.py --help
```

Полная резервная копия PostgreSQL сохраняет аккаунты, партии, отчёты анализа, задачи и статистику. Порядок создания и проверки дампа рабочего сервера приведён в [deploy/SERVER.md](deploy/SERVER.md). Копируйте дампы на отдельное хранилище: резервная копия на том же сервере не защищает от потери сервера. Обновление каталога исходных задач планируется отдельно от обычного обновления приложения.

На странице **Прогресс → Скачать прогресс** доступен экспорт попыток и расписания повторений в JSON, без пароля и сессий. Для созданных задач экспорт v2 также включает все личные задачи (в том числе ещё не решённые), использованные открытые задачи и их решения, чтобы восстановление не зависело от прежней базы. Старые копии v1 поддерживаются; история импорта, промежуточный анализ и готовые отчёты из раздела **Анализ** в JSON не входят — для полного переноса используйте резервную копию PostgreSQL. Восстановление в пустой аккаунт на новой установке выполняется командой `python -m app.restore_progress FILE --username USER` внутри backend-окружения. Импорт в аккаунт с существующими попытками, повторениями или личными задачами запрещён, чтобы не затереть данные и не удвоить статистику.

## Разработка

- `frontend/`: React, TypeScript, Vite, chess.js, nginx.
- `backend/`: FastAPI, SQLAlchemy, psycopg, Alembic, python-chess.
- `data/`: компактная база задач и сведения об источнике.
- `compose*.yml`, `deploy/`: развёртывание; актуальная инструкция рабочего сервера — [deploy/SERVER.md](deploy/SERVER.md).
- [API.md](API.md): контракт между фронтендом и бэкендом.

Фронтенд:

```bash
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на локальный Python-сервер. Бэкенд:

```bash
cd backend
uv sync --locked
# Задайте DATABASE_URL, AUTH_USERNAME, AUTH_PASSWORD, DATA_PATH,
# COOKIE_SECURE=false и ALLOWED_ORIGINS=http://localhost:5173.
uv run alembic upgrade head
uv run python -m app.bootstrap
uv run uvicorn app.main:app --reload
```

Локальная PostgreSQL для разработки доступна на `127.0.0.1:55432` после `docker compose -f compose.yml -f compose.dev.yml up -d db`. Используйте пароль из `.env`. Для анализа отдельно установите Stockfish и задайте `STOCKFISH_PATH`.

## Проверки

```bash
cd frontend
npm run build
```

Проверка фонового поведения интерфейса в Chromium (Python Playwright и Chromium): запустите Vite на порту 5174, затем `python frontend/tests/background-browser.py` из корня проекта. При необходимости задайте `TEST_FRONTEND_URL` и `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Проверяются скрытие вкладки, заморозка отсчёта браузером, возврат, ручная пауза и серверные команды запуска. Фоновый обработчик отдельно покрыт PostgreSQL-тестами `backend/tests/test_background_analysis.py`.

Backend-тесты работают с настоящей PostgreSQL и отдельной временной схемой. Укажите **отдельную тестовую базу**, не рабочую:

```bash
cd backend
TEST_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:55432/tactics_test uv run pytest
```

Пароль и URL в примере — шаблон. Тесты проверяют вход, защиту сессии, происхождение запросов, правильную стартовую позицию, скрытие ответа, решения, альтернативный мат, повторение и статистику.

## Проверка скорости движка

Для сравнения производительности серверов подготовлен воспроизводимый Stockfish `bench` с настройками анализатора: NNUE, MultiPV 2, один поток и 32 MiB hash. Команды запуска, сохранение JSON и правила сравнения NPS описаны в [BENCHMARK.md](BENCHMARK.md).
