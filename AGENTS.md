# Обновление основного сервера

## Окружение

- Репозиторий: `https://github.com/kimoleg200301/chess-trainer`, ветка `main`.
- SSH через Tailscale: `root@100.105.139.68`, порт `2222`.
- Основной сайт: `http://178.88.83.132:18080`; через Tailscale: `http://100.105.139.68:8080`.
- Каталог на сервере: `/opt/chess-trainer`. Его PostgreSQL — основная рабочая база.
- Ubuntu 24.04 в WSL2 без systemd; Docker Compose. Windows `18080` направлен на WSL `8080`; не меняй внутренний порт на внешний.
- Полный порядок обновления, бэкап и автозапуск описаны в [deploy/SERVER.md](deploy/SERVER.md).

## Правила

- Готовь изменения в рабочем репозитории, публикуй проверенный коммит в GitHub и обновляй основной сервер из `main`. Образы приложения собираются на сервере; GHCR в этом процессе не используется.
- Сохраняй серверные `.env`, `compose.wsl.yml`, `DEPLOYMENT.txt`, настройки автозапуска и том PostgreSQL. Изучи локальные изменения до обновления; не затирай их. Серверные `compose.wsl.yml` и `DEPLOYMENT.txt` ожидаемо могут быть untracked.
- Всегда используй `compose.yml` вместе с `compose.wsl.yml`: override отключает bootstrap восстановленной базы. `AUTH_PASSWORD=disabled` — предохранитель, а не пароль входа; аккаунты хранятся в PostgreSQL.
- Не запускай `app.bootstrap`, `scripts/configure.py`, `docker compose down -v` и удаление томов при обычном обновлении.
- Не добавляй в Git секреты, `.env` и дампы. Бэкапы и проверку сохранности данных выполняй на основной базе этого сервера.

## Порядок обновления

1. Проверь рабочее дерево, текущий SHA и изменения до выбранного коммита `origin/main`.
2. Перед изменением работающего приложения сохрани полный дамп PostgreSQL и серверную конфигурацию. Проверь размер и читаемость дампа через `pg_restore --list`, сохрани его копию вне сервера.
3. Обнови код через fast-forward, проверь Compose, собери образы и запусти контейнеры по [инструкции](deploy/SERVER.md). При ошибке остановись. После пересоздания backend перечитай конфигурацию nginx.
4. Проверь локальный и внешний health, журналы и затронутые функции. Вход, тренировку и анализ проверяй отдельным тестовым аккаунтом, сохраняя личную статистику пользователя; удали тестовые данные после проверки.
5. Сообщи установленный SHA, путь бэкапа, проверки и ограничения. Для изменений только документации пересборка и перезапуск приложения не нужны.

- Откат выполняется на этом же сервере к предыдущему проверенному коду с учётом совместимости схемы БД. Не восстанавливай старый дамп поверх новых пользовательских данных автоматически.
- При обычном обновлении приложения не перезапускай Windows/WSL, SSH и Tailscale. Автозапуск WSL: `/usr/local/sbin/chess-trainer-boot`; Windows: задача `ChessTrainer-WSL-Forward-18080` при входе пользователя.
