# Бесплатная проба на Render и перенос на VPS

Корневой `render.yaml` создаёт только два бесплатных ресурса:

| Ресурс | План | Назначение |
| --- | --- | --- |
| `tactics-trial` | Free Web Service | React + FastAPI + Stockfish в одном Docker-контейнере |
| `tactics-trial-db` | Free PostgreSQL 17 | Пользователь, задачи, результаты, повторения и отчёты анализа |

Фронтенд и бэкенд остаются отдельными проектами. Специальный `deploy/Dockerfile.render-free` собирает оба и передаёт путь к React через `FRONTEND_DIST`. На VPS стандартный Compose запускает их отдельными контейнерами.

## Запуск

1. Войдите в свой аккаунт Render. Платная подписка Workspace для этого не нужна.
2. Откройте [запуск из репозитория chess-trainer](https://render.com/deploy?repo=https://github.com/kimoleg200301/chess-trainer).
3. При необходимости подключите GitHub и выберите ветку `main`, Blueprint `render.yaml`.
4. Проверьте, что у **обоих** ресурсов указан план **Free**. Регион — Frankfurt.
5. В поле `AUTH_PASSWORD` задайте уникальный пароль минимум из 12 символов. Логин `AUTH_USERNAME` — `trainer`. Пароль вводится в Render, не в Git и не в переписку.
6. Запустите создание ресурсов. При первом старте выполняются миграции, создание пользователя и импорт 2500 задач.
7. После успешного запуска откройте URL сервиса `tactics-trial`, войдите и решите задачу. По адресу `/api/health` база должна отвечать, а `engine_available` должен быть `true`.

`DATABASE_URL` передаётся из созданной базы автоматически. `PUBLIC_HOST` берётся из hostname веб-сервиса; `COOKIE_SECURE=true` включает HTTPS-cookie. Для собственного домена задайте у сервиса `ALLOWED_ORIGINS=https://ваш-домен`.

Автоматическая публикация по обычному коммиту отключена (`autoDeployTrigger: off`). Проверенные обновления кода запускайте через **Manual Deploy**. Изменение самого Blueprint может синхронизировать ресурсы, поэтому проверяйте дифф `render.yaml` перед его применением.

## Ограничения бесплатного режима

По [официальной документации Render](https://render.com/docs/free), проверенной 31 октября 2026 года:

- Веб-сервис засыпает после 15 минут бездействия; первое открытие после паузы может быть медленным.
- Бесплатная PostgreSQL истекает через 30 дней и становится недоступна. После дополнительного периода для перехода на платный план она удаляется.
- У бесплатной PostgreSQL нет встроенных резервных копий.
- Ресурсы и доступность ограничены условиями Free. Это пробный запуск, а не постоянное бесплатное хранилище прогресса.

**До истечения 30 дней** откройте **Прогресс → Скачать прогресс** и сохраните JSON на своём компьютере. Экспорт содержит попытки, повторения и личные задачи, но не пароли и сессии. История импорта, промежуточный анализ и готовые отчёты из раздела **Анализ** в этот JSON не входят; для них нужна полная резервная копия PostgreSQL (`pg_dump`). После блокировки базы веб-экспорт уже не сможет прочитать данные.

Схема Blueprint и ссылки между ресурсами описаны в [Blueprint reference](https://render.com/docs/blueprint-spec). Кнопка запуска использует официальный механизм [Deploy to Render](https://render.com/docs/deploy-to-render). Фактическую готовность подтверждает успешное развёртывание в аккаунте и проверка URL, а не только валидация YAML.

## Перенос прогресса на собственный VPS

1. Установите Docker Compose на VPS и склонируйте тот же репозиторий.
2. Настройте домен и запустите Compose с `compose.vps.yml` по корневому README. PostgreSQL останется версии 17, фронтенд и API будут отдельными контейнерами.
3. Выполните первый запуск, чтобы создать пустой аккаунт и импортировать каталог задач. До восстановления не решайте задачи на новом сервере.
4. Скачайте последнюю копию прогресса из старого приложения до истечения базы.
5. Передайте JSON на VPS и скопируйте его в backend-контейнер:

```bash
docker compose exec -T backend sh -c 'umask 077; cat > /tmp/progress.json' < tactics-progress-YYYY-MM-DD.json
docker compose exec backend python -m app.restore_progress /tmp/progress.json --username trainer
docker compose exec backend rm /tmp/progress.json
```

6. Войдите в новый аккаунт и проверьте статистику и повторения. Импорт разрешён только в аккаунт без попыток и повторений; повторный импорт отклоняется. Пароль на VPS берётся из его собственного `.env`.
7. Сохраните исходный JSON отдельно. Для дальнейших резервных копий всего PostgreSQL используйте `scripts/backup.sh` и внешнее хранилище.

Если переносите полный `pg_dump`, восстановите его в пустую базу **до** запуска bootstrap, через клиент PostgreSQL 17 с `pg_restore --no-owner --no-acl`. Перенесите `AUTH_USERNAME` и `AUTH_PASSWORD` через защищённые настройки окружения: другое значение пароля намеренно изменит его и отзовёт сессии при старте.

## Платная конфигурация сохранена отдельно

`deploy/render-paid.yaml` содержит прежнюю схему с отдельными frontend/API-сервисами и постоянной PostgreSQL. Она **не применяется** по основной ссылке запуска. Её ориентир — $7 + $7 + $6, около $20/месяц до дополнительных расходов и налогов; [актуальные тарифы](https://render.com/pricing). Переход на неё — отдельное решение, не часть бесплатного запуска.
