# Приближение итоговой точности к Chess.com

Проверка выполнена 4 ноября 2026 года на открытых завершённых партиях
`kimskiy1114` с контролем `300+5`. Это персональная калибровка итогового процента,
а не воспроизведение закрытого CAPS2 или классификации отдельных ходов.

## Данные и независимая проверка

В публичных архивах за сентябрь–ноябрь были 123 партии с полем `accuracies`.
Из них по заранее фиксированным равномерным индексам внутри хронологических
групп выбраны 60: 36 для настройки коэффициентов, 12 для выбора формулы и
12 последних для окончательной проверки. Обе стороны одной партии всегда
относятся к одной группе. Отсутствующие оценки не заменялись выдуманными.

Исходные архивы: [сентябрь](https://api.chess.com/pub/player/kimskiy1114/games/2026/09),
[октябрь](https://api.chess.com/pub/player/kimskiy1114/games/2026/10),
[ноябрь](https://api.chess.com/pub/player/kimskiy1114/games/2026/11).
Набор состоит только из партий с опубликованной точностью, поэтому не является
случайной выборкой всех партий игрока. Новые ответы API могут изменять покрытие.

Сравнивались исходное среднее точностей ходов, степенное преобразование этого
среднего и две экспоненциальные функции средней потери оценки. Коэффициенты
подбирались только по обучающей части, семейство выбиралось по проверочной
с предпочтением более простой модели при разнице не больше 0,5 п.п.
После выбора формулы коэффициенты зафиксированы; окончательная выборка
не использовалась для повторной настройки.

## Формула и результат

Исходная точность хода и категории ходов сохранены. Дополнительный процент:

```text
round(100 * exp(-6.555042015529255 * mean(expected_loss)), 1)
```

Среднее берётся по надёжно оценённым невынужденным ходам игрока. Такой способ
сильнее учитывает крупные потери, чем арифметическое усреднение точностей ходов.

| Выборка игрока | Партий | Средняя абсолютная ошибка раньше | После калибровки |
|---|---:|---:|---:|
| Настройка коэффициента | 36 | 12,18 п.п. | 4,37 п.п. |
| Выбор формулы | 12 | 11,29 п.п. | 3,57 п.п. |
| Независимая проверка | 12 | 6,88 п.п. | 3,60 п.п. |

На независимой проверке средняя ошибка уменьшилась на 47,6%, систематическое
завышение — с +6,53 до +0,39 п.п. В диапазон ±5 п.п. попали 9 из 12 результатов
вместо 5. Максимальная ошибка осталась 8,73 п.п. Парный bootstrap по целым
партиям (5000 повторений) дал интервал уменьшения средней ошибки
[1,02; 5,57] п.п.; маленькая выборка и один игрок ограничивают переносимость.

Основной расчёт использовал Stockfish 19 с ускоренным профилем: один поток,
64 MiB hash, базовый бюджет поиска 200 000 узлов / 1 секунда и общий бюджет
хода 15 секунд. Внутренние повторные проверки могли использовать больший
бюджет. Это не штатный профиль приложения.

Отдельно проверен перенос на штатные настройки: Stockfish 19, два потока,
256 MiB hash, 2 млн узлов / 3 секунды на базовый поиск, общий бюджет хода
30 секунд и новый процесс на каждый ход. На трёх заранее выбранных тестовых
партиях пересчитаны все ходы игрока; ходы соперника явно оставлены неоценёнными.
Ошибка снизилась с 9,99 до 5,89 п.п. Два ранее сохранённых полных отчёта
версии 2 дали 8,11 → 5,84 п.п. Вместе это пять различных партий и
9,24 → 5,87 п.п., но только небольшая дополнительная проверка, не оценка
точности для всех игроков. На одной из трёх пересчитанных партий ошибка
составила 10,83 п.п. Формула после этих проверок не менялась.

## Расширение на соперника 5 ноября

Тот же зафиксированный коэффициент проверен для соперников в отложенных
12 партиях: средняя абсолютная ошибка уменьшилась с 10,21 до 3,85 п.п.,
максимальная — с 25,38 до 9,16 п.п. В диапазон ±5 п.п. попали 8 результатов
вместо 3; улучшились 10 партий из 12. Повторной настройки по этим результатам
не было, оценка стороны `kimskiy1114` не изменилась.

Дополнительно проверены три доступных на 5 ноября завершённых рабочих отчёта
версии 2 с исходными процентами Chess.com. Для соперников средняя ошибка
уменьшилась с 19,43 до 10,43 п.п., улучшились все три результата. Максимальная
оставшаяся ошибка — 17,57 п.п. Поэтому результат 3,85 п.п. на ускоренном профиле
нельзя обещать для штатного глубокого расчёта. Это небольшая проверка переноса,
а не новая обучающая выборка. [Данные проверки](benchmarks/accuracy-2026-11-05/opponents.json).

Профиль `kimskiy1114-300plus5-20261105-v2` включает `apply_to: both_players`:
он распространяется на обе стороны тех же партий с контролем `300+5`.
Область применения не расширена на партии других импортируемых ников.
Профили без `apply_to` сохраняют прежнее поведение только для указанного игрока.

## Поведение приложения

- Оригинальные `accuracies` из API показываются отдельно как «Точность Chess.com».
- Калибровка включена для обоих игроков в импортированных партиях `kimskiy1114` с контролем `300+5`
  и текущих отчётов версии 2. Для старых импортов контроль можно прочитать
  из заголовка сохранённого PGN. Явное поле контроля имеет приоритет.
- Приближение помечено `≈`. Партии других импортируемых ников и другие контроли сохраняют исходную оценку.
- Неполное покрытие, отсутствующая потеря оценки и одни вынужденные ходы
  не дают калиброванного процента для соответствующей стороны. Вторая сторона
  оценивается независимо. Пропуски не считаются идеальными ходами.
- Поле `summary.accuracy` сохраняет исходный результат. Дополнительное поле —
  `estimated_chesscom_accuracy`; метод и область применения доступны в API.
- Процент вычисляется при чтении сохранённого отчёта. Миграция, сброс ходов,
  запуск движка и изменение истории тренировок не требуются.
- При смене версии анализа профиль нужно проверить заново; автоматически
  переносить этот коэффициент на другой движок или другие настройки нельзя.

## Проверяемые материалы и повторение эксперимента

[Материалы](benchmarks/accuracy-2026-11-04/) включают зафиксированную модель,
метрики всех кандидатов, 120 строк с прогнозами обеих сторон, исходными
значениями, средней потерей и ссылками на партии, а также отдельные результаты
штатного профиля. Это позволяет проверить формулу и опубликованные метрики.
Кеш полных расчётов и сырые архивы не входят в приложение.

Это отдельный исследовательский запуск, не шаг обновления рабочего сервера. Выполняйте его в отдельной среде разработки; обслуживание основного сервера описано в [deploy/SERVER.md](deploy/SERVER.md). Команды ниже рассчитаны на Linux с указанным путём Stockfish; на Mac M3 используйте путь к своей нативной сборке и учитывайте отличие архитектуры при сравнении.

Для нового эксперимента сохраните ответы месячных архивов вне Git, затем:

```bash
uv pip install --python backend/.venv/bin/python numpy scipy
backend/.venv/bin/python scripts/calibrate_accuracy.py \
  --archive-dir /tmp/chess-archives --output-dir /tmp/chess-benchmark \
  --stockfish /usr/games/stockfish --workers 4 \
  --nodes 200000 --max-time 1 --max-position-time 15 --retry-unassessed
backend/.venv/bin/python scripts/fit_accuracy.py fit \
  --input-dir /tmp/chess-benchmark --output /tmp/chess-model.json
backend/.venv/bin/python scripts/fit_accuracy.py evaluate \
  --input-dir /tmp/chess-benchmark --model /tmp/chess-model.json \
  --output /tmp/chess-test.json
```

Скрипты не обращаются к рабочей БД. `selection.json` фиксирует партии и группы;
`--manifest` позволяет повторить заданный выбор. Настройки, контрольные суммы
движка и исходников сохраняются вместе с результатами. Для ограниченной проверки
штатной глубины предназначен `scripts/check_accuracy_depth.py`; сравнение
с зафиксированной моделью требует явных флагов `--allow-subset` и
`--allow-different-engine`. Новый набор данных означает новый эксперимент,
а не повторение опубликованного теста на неизменной выборке.
