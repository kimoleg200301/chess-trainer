# Учебные базы

## Готовые задачи Lichess

`puzzles.csv` содержит **2500 настоящих тактических задач** из [открытой базы Lichess](https://database.lichess.org/#puzzles). Это стартовая выборка, а не полная база сайта.

- Источник: <https://database.lichess.org/lichess_db_puzzle.csv.zst>.
- Дата получения: 31 октября 2026 года, UTC.
- Лицензия экспорта: [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/). Исходный формат и ссылки на партии сохранены.
- Фактический диапазон рейтинга задач: **600–2391**. Это рейтинг задач Lichess, а не рейтинг игрока FIDE.
- Фильтры: рейтинг 600–2400, минимум 20 сыгранных попыток в исходной базе, популярность не ниже нуля, хотя бы одна из десяти выбранных тем.
- Порядок выборки: первые подходящие строки официального экспорта. Выборка не заявляется статистически репрезентативной.
- Все 2500 исходных позиций и полных последовательностей ходов прошли проверку легальности через `python-chess`.

Одна задача может иметь несколько тем; сумма строк таблицы не равна числу задач. Дополнительные исходные метки также сохранены.

## Семантика позиции и решения

**Поле FEN описывает позицию до последнего хода соперника.** Перед показом задачи нужно применить первый ход из поля `Moves`. Решение ученика начинается со второго элемента. Сторона ученика определяется по очереди хода после применения первого элемента. Не показывайте исходный FEN как готовое упражнение.

## Обновление выборки

Из корня проекта:

```bash
uv run scripts/import_lichess.py
```

Скрипт объявляет собственные зафиксированные зависимости в формате PEP 723; `uv` устанавливает их в отдельное кешируемое окружение. Установка библиотек в системный Python не нужна.

Пример других параметров:

```bash
uv run scripts/import_lichess.py --limit 5000 --min-rating 800 --max-rating 1800 --themes fork,pin,skewer --max-download-mb 16
```

Импорт потоковый: прекращается после достижения цели, 100000 просмотренных строк или лимита сжатых сетевых данных. По умолчанию лимит скачивания — 16 MiB. При создании текущей выборки просмотрено 4890 строк и прочитано **327680 байт** сжатых данных; полный архив не скачивался. Код завершения `2` означает, что сохранена неполная выборка из-за ограничения, `1` — ошибку; `0` — достижение цели. При отсутствии подходящих задач прежний файл остаётся нетронутым.

Файл `puzzles.metadata.json` содержит параметры, фактические счётчики, время получения, число скачанных байт и SHA-256 CSV. Обновление CSV меняет только источник импорта; загрузка новых строк в PostgreSQL выполняется командой подготовки базы из основного README проекта.

## Собственная база из полных реальных партий

`public-games.pgn` содержит **40 полных рейтинговых партий** из [официального архива Lichess за январь 2013 года](https://database.lichess.org/standard/lichess_db_standard_rated_2013-01.pgn.zst). Архив распространяется по [CC0](https://database.lichess.org/). Выбраны первые завершённые стандартные партии длиной 20–180 полуходов; все ходы проверены на легальность. Основные линии, имена игроков, результаты, даты и ссылки на оригиналы сохранены. Комментарии и побочные варианты удалены. Это небольшая воспроизводимая стартовая подборка, а не репрезентативная выборка всех партий.

`generated-puzzles.json` — отдельный стартовый банк задач, **самостоятельно рассчитанных Stockfish 15.1 из этих партий**. Готовые решения из `puzzles.csv` при его создании не использовались. Отбор включает тактические возможности, которые игроки как находили, так и пропускали. Сохраняются только короткие решения с явно предпочтительным ходом ученика, проверенным завершением комбинации и материалом либо матом в конце. Поэтому генератор не обязан создавать задачу из каждой партии и каждого улучшения.

Текущий банк содержит **20 задач из 17 партий**: 1 дебютную, 12 из миттельшпиля и 7 из эндшпиля по описанной ниже эвристике. Есть вилки, связки, вскрытое нападение, взятие незащищённой фигуры, защитные и тихие ходы, мат в один и три хода. Большинство задач короткие и рассчитаны на начинающих; это стартовый банк, который можно пополнять анализом остальных моментов.

Рейтинг новых задач — предварительная эвристическая оценка, а не рейтинг Lichess. Темы определяются консервативными правилами по рассчитанному варианту; стартовая подборка покрывает только часть доступных мотивов. Метки стадии партии также эвристические: эндшпиль — не более 12 фигур вместе с пешками и королями, либо без ферзей и не более шести остальных фигур кроме пешек и королей; иначе дебют до десятого хода включительно, затем миттельшпиль.

`public-games.metadata.json` хранит URL и SHA-256 исходного архива, контрольные суммы корпуса и банка, сведения о каждой партии, параметры генерации и результаты отдельной проверки. Поле `source_ply` в банке — индекс хода ученика в исходной партии, начиная с нуля. Семантика `initial_fen` и массива `moves` такая же, как у задач Lichess: сначала применяется первый ход соперника, затем начинается решение.

Для воспроизведения из корня проекта нужны зависимости бэкенда, `zstd` и установленный Stockfish:

```bash
backend/.venv/bin/python scripts/build_public_bank.py --download --analyse --engine /usr/games/stockfish
backend/.venv/bin/python scripts/verify_public_bank.py --engine /usr/games/stockfish
```

Скачивается один архив размером около 17 MiB; жёсткий лимит — 32 MiB. Он кешируется в игнорируемой папке `artifacts/`. В репозиторий попадают только выбранные партии, задачи и метаданные. Stockfish использует один поток и 64 MiB для хеш-таблицы. По умолчанию базовый поиск ограничен 40 000 узлами / 0,2 секунды на пробу, проверочный — 250 000 узлами / 0,6 секунды; срабатывает первое достигнутое ограничение. Текущий банк дополнительно пересчитан с проверочным лимитом 500 000 узлов / 2 секунды. Генерация перебирает конечное число позиций и останавливается после 24 подходящих задач либо исчерпания корпуса. На слабом процессоре отбор может занять несколько минут и дать меньше задач.

Отдельный аудит повторно сверяет FEN с полной исходной партией, легальность всех ходов, стабильные идентификаторы и каждый ход ученика с новым поиском до 1 000 000 узлов / 3 секунд с очищенной хеш-таблицей. Для материальных решений он проверяет лучший ответ соперника и отсутствие необходимого продолжения комбинации; варианты с форсированным матом должны заканчиваться настоящим матом. Аудит завершается с ошибкой, если хотя бы одна задача не проходит проверку.

Для повторной проверки генератором только уже выбранных моментов можно добавить `--refresh-existing` к команде с `--analyse`. Для изменения вычислительных ограничений доступны `--quick-nodes`, `--verify-nodes`, `--max-time`; результаты могут различаться между версиями движка и процессорами. После изменения банка необходимо снова выполнить аудит и подготовку PostgreSQL из основного README.
